**Create Ticket** locks BTS into a **ticket** — a time-locked stake that boosts your governance voting power the longer you lock. You choose a lock type (e.g. 180 / 360 / 720 days, or forever) and the amount, broadcasting `ticket_create`. Existing tickets can be modified with `ticket_update`.

**Open in the app:** [Create Ticket](/create_ticket.html).

## What it does

<CardGrid>
  <Card title="Lock for power" icon="lock">
    Longer locks grant more effective voting weight.
  </Card>
  <Card title="Lock types" icon="clock">
    180 / 360 / 720 days, liquid, or forever.
  </Card>
  <Card title="Adjust" icon="settings">
    Change lock type or add funds via `ticket_update`.
  </Card>
</CardGrid>

## How to use

<Steps>

1. Open **Create Ticket** from the homepage under *Governance*.

2. Choose a lock `target_type` and the BTS amount to lock.

3. Authorize → `ticket_create`.

4. Later, change the lock type or add more funds via `ticket_update`. Your tickets dashboard shows total locked BTS, effective voting power, and a per-type breakdown, with per-row updating.

</Steps>

<Aside type="note" title="target_type values">
  `target_type` is the lock duration enum: `0` = liquid, `1` = 180 days, `2` = 360 days, `3` = 720 days, `4` = forever. Voting-power boosts: liquid 1×, 180 days 2×, 360 days 4×, 720 days and forever 8×.
</Aside>

<Aside type="tip" title="THUMBSUP.1 (mainnet)">
  Locking BTS into tickets requires an equal THUMBSUP.1 balance — a token issued by the `abit` account. If you're short, the page's request card builds a `proposal_create` asking `abit` to transfer you the deficit (7-day expiry, 1-hour review, fee paid by `abit`). Request no more than your BTS balance.
</Aside>

## Operations used

<Tabs>
  <TabItem label="ticket_create">

```json
{
  "account": "1.2.x",
  "target_type": 1,
  "amount": { "amount": 10000000, "asset_id": "1.3.0" },
  "extensions": []
}
```

  </TabItem>
  <TabItem label="ticket_update">

```json
{
  "ticket": "1.18.x",
  "account": "1.2.x",
  "target_type": 2,
  "extensions": []
}
```

With an added deposit:

```json
{
  "ticket": "1.18.x",
  "account": "1.2.x",
  "target_type": 2,
  "amount_for_new_target": { "amount": 5000000, "asset_id": "1.3.0" },
  "extensions": []
}
```

Lock-forever tickets are frozen and cannot be updated; picking the ticket's current type is blocked, and choosing liquid hides the extra-amount field.

  </TabItem>
</Tabs>

| Field | Meaning |
| --- | --- |
| `account` | Your account (`1.2.x`). |
| `target_type` | Lock duration enum (`0` liquid, `1` 180d, `2` 360d, `3` 720d, `4` forever). |
| `amount` | BTS to lock on create. |
| `ticket` | The `1.18.x` ticket object id being updated. |
| `amount_for_new_target` | Extra BTS when moving to a new lock type. |
