**Change Password** derives fresh owner, active and memo keys from a new password and broadcasts a single `account_update` replacing all three authorities. Use it when a password may be compromised — or routinely, as hygiene.

**Open in the app:** [Change Password](/change_password.html).

## What it does

<CardGrid>
  <Card title="New keys" icon="key">
    Owner, active and memo keys derived from your new password.
  </Card>
  <Card title="One broadcast" icon="zap">
    A single `account_update` rotates everything at once.
  </Card>
  <Card title="Validation" icon="check">
    Live checks that the keys match the expected prefix before signing.
  </Card>
</CardGrid>

## How to use

<Steps>

1. Open **Change Password** from the homepage under *Settings*.

2. Enter a new password (twice) and review the derived public keys.

3. Authorize. The app broadcasts `account_update` with the new authorities.

4. Remove the account from Beet/BeetVault and re-add it with the new password — Beet keeps the old password-derived keys and will fail to sign until you do.

</Steps>

<Aside type="caution" title="Don't skip step 4">
  Rotating keys on-chain is only half the job. Until you re-import the account into Beet with the new password, signing keeps failing against the old keys.
</Aside>

## Operation used

Password rotation broadcasts `account_update` (operation `6`) with replaced authorities:

```json
{
  "account": "1.2.x",
  "owner": {
    "weight_threshold": 1,
    "account_auths": [],
    "key_auths": [["BTSnewOwnerKey...", 1]],
    "address_auths": []
  },
  "active": {
    "weight_threshold": 1,
    "account_auths": [],
    "key_auths": [["BTSnewActiveKey...", 1]],
    "address_auths": []
  },
  "new_options": {
    "memo_key": "BTSnewMemoKey..."
  },
  "extensions": {}
}
```

| Field | Meaning |
| --- | --- |
| `account` | Your account (`1.2.x`). |
| `owner` / `active` | Replacement authorities (threshold + key auths). |
| `new_options.memo_key` | Replacement memo key (other options echoed). |
